# P25 Phase 1 receive

P25 Phase 1 conventional receive: C4FM at 4800 baud, the frame sync, the Network ID, and the plan for voice. The
receiver in `core/p25/` starts from sliced symbols, so it works with any demodulator that supplies one of four
deviations per symbol. Voice and trunking are not implemented yet.

Sources: TIA-102.BAAA (the common air interface) and a real conventional call, NAC 0x293, used to pin every constant
below.

## 1. Modulation and symbols

Phase 1 is four-level FM (C4FM) at 4800 symbols/s, two bits per symbol, 9600 bit/s gross. The four deviations are
-1800, -600, +600 and +1800 Hz. A slicer returns one of the four symbol values below; the dibit mapping is fixed by
the standard.

| Deviation | Symbol | Dibit | Bits, first sent first |
|---|---|---|---|
| -1800 Hz | -3 | 11 | 1, 1 |
| -600 Hz | -1 | 10 | 1, 0 |
| +600 Hz | +1 | 00 | 0, 0 |
| +1800 Hz | +3 | 01 | 0, 1 |

An FM discriminator can invert the whole alphabet (a conjugated I/Q input). That is a rotation of every dibit by 2;
it is the only rotation a C4FM stream can present. The sync search tries rotations 0 and 2.

## 2. Frame sync

Every data unit opens with the same 48-bit frame sync, `0x5575F5FF77FF`, 24 dibits:

```
1 1 1 1 1 3 1 1 3 3 1 1 3 3 3 3 1 3 1 3 3 3 3 3
```

Only the outer symbols (-3 and +3) appear, so a receiver may correlate up to 4 mismatched dibits of 24 and still
lock. The sync is contiguous: no status symbol is inserted inside it.

## 3. Status symbols

One 2-bit status symbol replaces every 36th on-air dibit. The count starts at the sync's first dibit, so the first
status symbol is at dibit 35 from that point (synchronously: after 35 data dibits), then at 71, 107, and so on. The
NID's 32 data dibits are therefore not the 32 that follow the sync on air: the status symbol at 35 must be removed
first. A decoder that ignores this reads a plausible but wrong NID.

## 4. Network ID and BCH

The 64-bit NID follows the sync: a 63-bit BCH(63,16,11) codeword and a flag bit. The codeword is systematic: the 16
information bits are the 12-bit NAC and the 4-bit DUID, then 47 parity bits.

| Field | Bits | Meaning |
|---|---|---|
| NAC | 12 | network access code |
| DUID | 4 | data unit ID: the frame type |
| BCH parity | 47 | BCH(63,16,11) over the first 63 bits |
| flag | 1 | 1 for LDU1/LDU2, 0 for every other DUID |

The code is binary BCH over GF(2^6) with primitive polynomial x^6 + x + 1 and roots alpha^1..alpha^22. Its generator
is `0xCD930BDD3B2B`; it corrects up to 11 bit errors. The 64th bit is not a parity bit: it is a fixed per-DUID flag,
so a decoder must check it against the decoded DUID.

| DUID | Frame |
|---|---|
| 0x0 | HDU, voice call header |
| 0x3 | TDU, terminator |
| 0x5 | LDU1, voice with link control |
| 0x7 | TSDU, trunking signalling |
| 0xA | LDU2, voice with encryption sync |
| 0xC | PDU, packet data |
| 0xF | TDULC, terminator with link control |

## 5. Validated receiver

`core/p25/p25_phy.c` and `core/p25/p25_bch.c` implement sections 1 to 4. They take sliced symbols, correlate the sync
with both possible rotations, remove the status symbols, collect the 64 NID bits, BCH-decode them and report the
NAC, DUID, corrected error count and flag. `tests/host/p25PhyTest.c` checks the BCH code to its correction radius
and decodes two real LDUs (NAC 0x293, one LDU1 and one LDU2) with zero corrected bits, including the polarity-flipped
case.

The receiver needs 4800 baud symbols from the radio. A modem with a raw-symbol or physical-layer receive path can
supply them; the chip's registers and receive buffers are on its modem page. A software demodulator from
discriminator audio is the fallback, but the audio must be wide enough for the 4FSK (the voice-band tap is not).

### 5.1 Bench probe

CONFIG_P25_PROBE builds a probe that puts the HR_C7000 into its physical-layer receive test mode with the P25 frame
sync and logs the raw receive RAM (`modem-hrc7000.md` 2.11). Tune the radio to the channel and leave it idle, then
`rfoundry_debug.py radio p25 start`, wait for a transmission, `radio p25 dump`, and `log`. `radio p25 stop` restores
the modem. The switch needs CONFIG_DEBUGLINK and CONFIG_DMR, and on a full image a feature is dropped to make RAM
room (the DM-32UV probe build uses `CONFIG_APRS=n`, 0.5 KB free otherwise).

The dump answers the front-end question before any P25 stack work: whether the chip's deframer accepts the P25 sync,
which of the four sync slots matched, and what bit order the 264-bit block comes out in.

### 5.2 Continuous-mode stream (bench, 2026-11-04)

The working set-up is `WORK_MODE 0x02` (continuous) with the P25 frame sync in the MS/BS/TDMA receive-sync registers;
`0x22` (timeslot) reported slot-abnormal on a P25 control channel. On `SYS_INTERP_LIST == 0x800` (PHY_RX; the
datasheet's figure 71) the chip appends 33 bytes (264 bits) at RX RAM `0x33`; `PHY_RDY` (`0x1000`) is the 30 ms slot
clock and must not be taken for a block, which is what made an earlier probe read a stale block forever.

The 264-bit chunks are a sliding window of the demodulated symbol stream, not frame-aligned. The first chunk after
`start` is sync-aligned: the 48-bit sync sits at bit 20 (the two 10-bit slot-type fields of the datasheet's
`SyncType = 2` layout come first), and the NID's post-sync info starts 88 bits after the sync, i.e. bit 156 of the
chunk. The 88-bit gap is DMR-shaped filler the chip leaves between the sync and the info; a wide search for the NID
also lands on a false BCH codeword inside it, so the decoder pins the offset. The P25 status symbol at NID dibit 11
is present in the info and must be dropped before the BCH decode, exactly as in section 3.

With the probe accumulating seven consecutive chunks, every capture decoded **NAC `0x293`, DUID `0x7`** (TSDU) with
3-4 corrected bits; the radio's `p25p nid` log line repeated it on every dump. The BCH decoder is
`core/p25/p25_bch.c`, linked only with `CONFIG_P25_PROBE`.

## 6. Voice and what is open

| Item | State |
|---|---|
| NID, NAC, DUID | Done and on-air checked against a capture |
| LDU voice framing | Open: the LDU structure, deinterleaving and the Golay, Hamming and trellis codes |
| IMBE voice | Open: the ISC-licensed `mbelib` decodes IMBE 7200x4400; it is third-party code to vendor and gate |
| Trunking | Open: TSBK, the trellis code and the control channel |
| Symbol source | Bench: the HR_C7000 continuous PHY receive gives the demodulated stream and decodes the NID (5.2); the sliding chunks still need frame reassembly |

The IMBE decoder is the only part that is not specified by the channel: `mbelib` (ISC) supplies it, and its notice
must travel with it. It is not in the tree yet.
